## Architecture

The installed `silkscreen` package lives under `engine/` (setuptools packages only `engine/`), with the Cloud Run surface in `service/`. The core pipeline is: parse a `.kicad_pcb` file, solve placement with CP-SAT, write the placements and board outline back into the file. A generated run additionally draws a `.kicad_sch` and lays copper, so it leaves a whole KiCad project rather than one placed board. The board file is the API — there is no KiCad process, plugin, or IPC anywhere. The design is layered: the deterministic kernel makes no network calls; `agents/` owns the normal Gemini calls; optional Ollama/Tinker placement adapters stay behind the experimental gate; and `service/` is the only place GCP lives. Each layer keeps an offline stand-in (`ScriptedModel`, `MemoryFactStore`) so the whole suite runs with no keys.

Core engine modules, in dependency order:

- **`units.py`** — every dimension in the codebase is an **integer nanometre** (KiCad's internal unit). No floats flow through the pipeline; unit confusion (mm/mil/nm) is treated as a board-destroying bug class. Provides `mm()`/`mil()`/`to_mm()` and grid quantisation (`DEFAULT_GRID_NM` = 0.05 mm, `DEFAULT_CLEARANCE_NM` = 0.25 mm).
- **`packing.py`** — the OR-Tools CP-SAT placer. `pack(parts, nets=..., clearance_nm=..., time_limit_s=...)` minimises HPWL wirelength plus board area and returns a `PackResult` with status `OPTIMAL` / `FEASIBLE` / `FALLBACK` (a shelf-pack fallback fires when CP-SAT finds nothing in budget). `FEASIBLE` is the normal outcome on real boards. Determinism requires `workers=1` (the default) — multi-worker CP-SAT is non-deterministic regardless of seed. Power nets are down-weighted (not dropped) via the `is_power_net` heuristic in kicad.py. `edge_refs`/`rotatable_refs` naming a ref not on the board is a hard error, not a no-op.
- **`kicad.py`** — `.kicad_pcb` read/write via `kiutils` (pure Python). `load_board` then `extract_parts` yields `FootprintInfo` (courtyard extents from `F.CrtYd`, falling back to the pad bounding box; per-pad offsets; pad-to-net map). `extract_nets`/`extract_wires`/`to_parts` build solver input. After solving, `apply_placements` moves footprints and `set_board_outline` draws `Edge.Cuts` (without it the board has no boundary and edge constraints mean nothing), then `save_board`. **Coordinate frames:** the solver works Y-up; KiCad is Y-down. kicad.py owns the flip at both boundaries (pad offsets in, placements out) — never convert anywhere else. Output format is `20240108` (KiCad 7–8). Geometry extraction is shape- and rotation-aware (PR #6): `_courtyard_points` dispatches on graphic type — `fp_poly` vertices, exact circle bounds, arc bulge via `_circumcentre` — and `_rotate_mm` maps footprint-local geometry through the footprint's existing angle, exact at any rotation, not just 90° steps. `extract_parts` and `apply_placements` share one identity rule, `_placer_ref` (reference designator, falling back to library name), and `to_parts` raises `ValueError` on duplicate refs or on footprints with neither — identity problems raise instead of silently no-opping, the same convention as `edge_refs`. The bug class all of this guards against never raises on its own: the solver reserves a box that doesn't match the part actually written, the run reports success, and the opened board has parts stacked on each other. Regression tests for this class compute expected geometry from the raw file with independent math that never calls kicad.py (the overlap truth function in `engine/tests/test_kicad.py`) — a check written in terms of the code under test would share its blind spot.
- **`netlist.py`** — validated circuit IR, the contract between an LLM and anything touching KiCad. `parse_circuit_spec` accepts raw model output (fenced JSON tolerated), and **collects all validation failures into one `ValidationError`** so the whole batch can go back to the model as a single repair prompt. Connections require pin-level terminals (`C1.1`, not `C1`) because "one leg of this capacitor to this pin" must be expressible.
- **`schematic.py`** — emits a complete `.kicad_sch` plus the `.kicad_pro` that ties it to the board, from the same `CircuitSpec`. Symbols are **generated, not looked up**: the file carries its own `lib_symbols`, so it opens where no KiCad library is installed and cannot resolve to a different part than the one drawn. Connections are a short wire stub per pin to a **net label**, not point-to-point wires. **Coordinate frames:** symbol libraries are Y-up, the sheet is Y-down, and `_pin_on_sheet`/`_stub_on_sheet` are the only two places that cross — reaching for `SymbolPin.stub` directly and adding its symbol-local `dy` to a sheet coordinate is how every passive's net label ended up drawn on its own body. The schematic and the board must agree on what `C3` is, which is what `CircuitSpec.assign_refs` exists for: both emitters call it rather than numbering parts themselves.
- **`routing.py`** — a two-layer A* grid maze router over a 0.25 mm lattice with an explicit via cost, nets routed one at a time. **Not a competitive autorouter and it does not pretend to be:** a uniform grid cannot reach every pin of a fine-pitch package, and the contract is honesty — every net it cannot finish is named in `RouteResult.unrouted` with a reason and left as ratsnest. A refusal names the nets it covers too, or `completion` reads an empty result as 100%. **Clearance is enforced inside the search**, against a map of committed copper centrelines, not by the halo `_commit` writes: that halo cannot claim a node another net already owns (pad keep-outs own many), so relying on it produced real shorts. Vias are tracked separately from tracks because a barrel is wider and the neighbour's shape sets the spacing. Two search budgets bound the work, in **node expansions rather than seconds** — the same design must route the same way twice — sized from measurement (400k total, 150k per net). Order traps get a bounded **rip-up-and-retry** pass after the first pass: a blocked net probes with foreign committed copper made penalty-passable (pads, plated-hole annuli and everything else in the pre-copper base state stay hard), the nets the probe crosses are lifted and the maps rebuilt by replaying survivors onto that base (never by un-marking, because halos overlap), the blocked net routes strictly, and the lifted nets re-route — a lifted net that fails stays named (`"ripped up to free a channel for …"`), eligible to rip in its own turn, everything capped per net and in rounds (`max_ripups`, default 8; `max_ripups=0` is the pre-rip-up router), inside the same expansion budget. A probe that dies of budget is reported as a budget death, never as "unroutable even with copper lifted" — the two reasons send a person to different fixes.


- **`spice/`** — SPICE simulation as a **verifier**, not a waveform viewer: it answers pass/fail with a signed margin rather than drawing a trace. DRC checks geometry; this is the only thing in the repo that checks *function*. It is designed for an agent loop and, since 2026-09-06, it is in one — **opt-in, and shaped exactly like the sourcing stage**. `agents/simulate.py` is the `agents/sourcing.py` shape applied to behaviour: `propose_testbench` shows the model the validated spec and the intent and asks for a testbench in the `spice/spec.py` JSON format (the same format the MCP `simulate_circuit` tool takes — one door, not two) plus the specification clauses the intent implies, each with a `critical` flag; `parse_testbench_response` batches every failure — JSON, the bridge's own list, and `build_deck`'s cross-check against the circuit — into one `TestbenchValidationError` for a single repair prompt (`max_repairs` default one), then gives up loudly with a warning; a `ModelError` is not wrapped; `SIMULATE_MARKER` (`SIMULATE-TESTBENCH v1`) keys `ScriptedModel.by_marker`; and `strict=True` is forced onto every proposed testbench. `simulate_circuit` decides in cost order and **two of its outcomes spend no model call at all**: `unsimulatable` (the spec holds a `Device` — every device is a pin map with no model — or a crystal; the parts are named) and `unavailable` (no ngspice, with the install hint) are decided from the spec and the machine before the model is asked; then `no_testbench` (the budget spent) and `ran` (every clause with pass/fail, the measured value and a signed margin, in a `SimulationResult` with `as_dict()` — the agents-layer receipt, not `spice.SimulationResult`, which is a set of waveforms with no failed variant by design). `simulate_stage`/`SimulationJob`/`start_simulation_stage` in `agents/stages.py` mirror the sourcing trio: started right after `placement_repair_stage` on a worker thread (it needs only the spec), joined after enclosure and sourcing and before review — but note the **joins** are ordered, not the **calls**: the three lanes genuinely race on their threads, and what actually keeps a `ScriptedModel` deterministic is `by_marker` keying on each lane's own marker (measured 2026-09-07; `WORKER_CALL_ORDER` in `engine/tests/test_agents.py` records the counter-example), and a `SpiceError`/`ValueError` inside the stage becomes a `simulation.failed` event plus status `failed` naming it — the board is still the product. Events are `stage.start`/`stage.done` with `stage: "simulation"`, `simulation.round` per rejected answer and `simulation.clause` per clause. **The decision on a failed clause:** it never fails the run; it becomes a `SimulationFinding` on `result.simulation.findings` — `blocker` when the model marked the clause critical, `warning` otherwise — kept apart from `PipelineResult.findings` because the critic's `Finding` carries no provenance field and a simulation verdict dressed as a datasheet citation would lie about where it came from. Plumbing: `generate_pcb(simulate=False, simulator=None)` on both drivers (`simulate_start`/`simulate` nodes in the ADK graph), `--simulate` on the CLI (one line per clause with its margin, or the one sentence saying why there is no verdict), `"simulate": true` on `/generate` (an additive `simulation` block, `None` plus a warning if the stage did not run), and `PipelineResult.simulation`. `engine/tests/test_simulate_stage.py` drives the verdict path through a fake `Simulator` and gates one real-ngspice test the `test_spice.py` way. Not yet reached from `service/steps.py`, the desktop overlay or the Slack/Workspace front ends — a step route would need a `simulate` step that starts `start_simulation_stage` at `place` the way `sourcing` does and a `background` entry while it runs. The MCP tools `simulate_circuit` and `spice_capabilities` (`engine/silkscreen/mcp/server.py:143,158`) remain, though **no MCP client is configured in this repo** (no `.mcp.json`, no `mcpServers` block, no Tauri sidecar — only the `silkscreen-mcp` console script in `pyproject.toml`), as do `scripts/simulate_demo.py` and direct library use. The design rationale below is why the module is shaped the way it is. `deck.py` turns a `CircuitSpec` plus a `Testbench` (sources, one analysis, models) into a netlist; `measure.py` extracts declarative quantities (rise time, ripple, gain, `abs_max` for absolute-maximum ratings); `assertions.py` turns a specification into pass/fail with the measured number and a **signed margin** on every clause; `simulators.py` puts ngspice and LTspice behind one interface; `raw.py` reads both rawfile dialects; `spec.py` is the JSON bridge the MCP `simulate_circuit` tool uses. Design rules, all load-bearing: **nothing returns a quiet zero** — every failure path raises a specific error from `errors.py`, because an agent that gets an empty result concludes the circuit is fine; a measurement with no answer (rise time of a flat signal, a probe on an absent node) raises rather than returning 0.0, and fails its clause rather than passing vacuously. Two boundaries are stated rather than hidden: **a `Device` is a pin map with no behaviour**, so simulating one needs a caller-supplied `SubcircuitModel` and otherwise raises `UnsimulatableError` naming the part (a crystal is the same case); and **a circuit is not a testbench** — the IR never says what drives it, so `Testbench` is separate and a source on a net the circuit lacks is an error, not a floating node. ngspice exits **zero** on a singular matrix and writes a well-formed rawfile, which is why `RunOutcome.warnings` exists and why `Testbench(strict=True)` (promoting warnings — a substituted generic diode, a floating pin — to errors) is the right default for an agent verifying a spec. Values follow SPICE's own syntax exactly (`M` is milli, `MEG` is mega) and reach the deck as scientific notation so the simulator cannot reinterpret a suffix; net names are sanitised to SPICE nodes and relabelled back on the way out, so a caller only ever sees its own vocabulary. Real data is never passed through `abs` — a node at -5 V must not measure as +5 V and pass an absolute-maximum check it violates. Regression tests check simulated numbers against closed-form theory computed inline (`tau*ln(9)`, `1/(2*pi*R*C)`), the same independent-math discipline `test_kicad.py` uses for overlap.

- **`enclosure/`** — AI-generated cases for the boards the pipeline emits, built like a CAD engineer works rather than a style picker (v2, decided 2026-09-03 after a survey of the open-source AI-CAD field; the reasoning and frozen contracts are in `docs/ai-cad-plan.md` under "v2"). The model proposes JSON only (`parse_enclosure_spec` batches every failure, the `netlist.py` convention; ENCLOSURE-SPEC v2 adds `mount`, `insert`, `material` and a `snap` lid) and never writes SCAD or code. Every mechanical number lives in `rules.py` (FDM fits, heat-set insert bores, ring-lip geometry, connector *plug* envelopes, vent and overhang limits, sourced from YAPP_Box, kicad2freecad-enclosures, turbocase and NopSCADlib) and every board number comes from `board_shape.py` (courtyards, heights from a class table or the footprint's `Height` property, mounting holes, connector class). `cad.py` builds real B-rep solids with build123d/OCCT — standoffs at the board's mounting holes, cutouts sized from the mating plug rather than the receptacle courtyard, elephant-foot chamfers — and exports a labelled STEP assembly plus two STLs — STEP is primary, ISO 10303-21 is ASCII and self-contained, and it is what `/generate` ships inline (the one-shot route exports into a `TemporaryDirectory` and reads the text back). `kernel.py` is the acceptance gate: thirteen frozen clauses measured on the B-rep by the kernel, each with a **signed margin** (board clash volume, headroom, boss concentric with its hole, every cutout admits its plug, lid mates, minimum wall, overhang in the printed orientation, …), reported in full and never a quiet zero. `snapshot.py` is a dependency-free software renderer whose multi-view packet is advisory only — research says property tests beat render-and-look, so renders never gate. The kernel is the **only** enclosure engine since 2026-09-08 (docs/ai-cad-plan.md v3): it is the `cad` extra (`pip install -e ".[cad]"`, gated in tests like ngspice via `needs_build123d`, installed by CI on all three OSes and by the Dockerfile), and where it is absent the case step **refuses in words** naming that command — `propose_enclosure` raises `KernelUnavailable` before spending a model call, the stage turns that into an `enclosure.failed` event and `result.enclosure is None`, and the board is still the product. A silent degrade to a lesser case is the one unacceptable outcome, which is why the v1 OpenSCAD emitter, its fit verifier and the OpenSCAD CLI wrapper were deleted rather than kept as a fallback. Frames: `cad.py` geometry is the assembled frame (X as KiCad, Y flipped so `front` is the KiCad max-Y edge, Z up); the lid is stored in its printed orientation with `lid_assembled` carrying it onto the base, so printability checks see what the printer sees and mating checks see what the user sees. Integer nanometres throughout with mm appearing only at the single crossing into the kernel.
- **`models3d.py`** — the KiCad-library 3D model each generated land pattern claims, as one `(model "${KISYS3DMOD}/<library>.3dshapes/<name>.step" …)` line per footprint in `board.emit_kicad_pcb`. A `.kicad_pcb` carries no Z, and `kicad-cli pcb export glb` (which the order step runs) draws a component only when its footprint names a model, so a board without these exports as a bare substrate. The models are **looked up, not shipped**: `KISYS3DMOD` is the legacy alias every KiCad since 5 maps onto its own versioned model directory, so one spelling opens in whichever KiCad the engineer has. The one rule: each table entry is a claim that the library model has the same body and pin pitch as the land pattern drawn, so the table is deliberately conservative — a package with no exact counterpart (a 2-pin 1210 crystal, the 0.5 mm-pitch LQFP-44 against the library's 0.8 mm one, the narrow-body SOIC-20/24/28 against the library's wide ones) maps to `None` with `why_unmatched` giving the reason, never to a picture of a different part. `engine/tests/test_models3d.py` checks every path the table can produce against the installed library, gated on it being present (the ngspice convention), so a renamed library file cannot leave a dangling path.
- **`sourcing.py`** — the bill of materials as a contract between a model and the order step, deterministic and network-free (`agents/sourcing.py` owns both the model and the probe). `bom_rows` derives one `SourcingEntry` per placed part from the board alone — `kind` from the ref prefix (R/C/L/D/Y, else `device`), `model3d` from `models3d.model_for` with `model3d_note` carrying the reason when there is none; `parse_sourcing_response` validates the model's answer the `netlist.py` way, every failure batched into one `SourcingValidationError` (unknown, duplicate or missing ref, non-string field, non-http(s) URL, an MPN over 64 characters); `bom_csv` writes a frozen column order with `\n` line ends so the same rows give the same bytes. The vocabulary is the honesty rule, and every word in it is earned by something the code did. `mpn_status` is `verified`, `proposed` or `none`: `verified` only when a distributor was configured and answered that it lists that exact part number, `proposed` when a model named one and nobody confirmed it, `none` when no part number exists. The distributor is `agents/distributor.py` — a Mouser Search API v2 client behind a `Transport` Protocol (the `meetings.meet`/`googleapps.transport` seam, so the suite never opens a socket), an exact-match host allowlist enforced at request construction for every transport including the fakes, and no verdict, warning or exception message that carries the request URL (the key travels in the query string, which is where Mouser reads it). It answers three verdicts — `verified`, `unlisted`, `unavailable` — and `verify_mpns` applies them to BOM rows: a hit sets `mpn_status="verified"` plus `distributor_sku` and `distributor_url`; an `unlisted` or `unavailable` row **stays `proposed`** and carries the reason in `verify_error`, in words, never a quiet `none`. The first `unavailable` stops the batch (a dead API is not asked N times) and every row it never reached says "not asked" with the same reason, as does every row past the `DEFAULT_VERIFY_BUDGET_S` (20 s) budget. Two things `verified` still does **not** mean: not that the part is in stock, and not that the package matches the land pattern — Mouser's `Package / Case` is free text that cannot be compared to a footprint mechanically, so it is passed through in the note and never used to downgrade a hit. With no `MOUSER_API_KEY` there is no verifier at all (`from_env` returns None), every row stays `proposed`, and that is the honest word for an MPN nobody checked. `datasheet_status` is `verified` only when a probe saw `%PDF-` at the URL (`not_pdf` for a reachable HTML viewer page, `unreachable` for anything that stopped the probe, `unprobed` when the probe budget ran out before that URL, `none` when no URL was proposed). A null from the model is worth more than an invented part number, and the prompt says so.
- **`specreview.py`** — the agenda a finished run hands a human, so a run ends in a booked half hour rather than a wall of text. `parse_spec_review` is validated model output the `netlist.py` way (fenced JSON tolerated, every failure batched into one `SpecReviewValidationError` for a single repair prompt), and its bounds *are* the feature: `SUMMARY_MAX_CHARS` 400, one to eight items, `MIN_TOTAL_MINUTES`/`MAX_TOTAL_MINUTES` 15–60, `SOURCES` frozen at `review`/`route`/`kernel`/`sourcing`. An item whose `refs` name nothing the board contains is **dropped** (the `review.py` hallucination filter again, switched on by `known_refs`) and each drop is reported in `SpecReview.dropped` — a filter that drops silently is indistinguishable from a model that said nothing. The bounds are checked against what the model proposed, before the filter runs, so the repair prompt talks about the answer actually given. Three states stay three representations: `SpecReviewResult.review is None` (the model gave nothing usable, with a warning), a `SpecReview` with empty `items` (**a real answer** — nothing needs a meeting), and no result at all (the stage never ran); `needs_meeting` is false for the first two, because a meeting must never be booked off a failure. `agents/specreview.py` is the `agents/sourcing.py` shape applied to it — `evidence_block` renders findings, unrouted nets, failed kernel clauses (with signed margins) and sourcing gaps, duck-typed because those come from three layers that do not import each other, and returns the refs it mentioned as the default `known_refs`; `SPECREVIEW_MARKER` (`SPEC-REVIEW-AGENDA v1`) keys `ScriptedModel.by_marker`; one repair round then it gives up loudly; a `ModelError` is not wrapped; and **with no evidence the model is not called at all** (asking a model to summarise an empty list is how an invented agenda is born). The scheduling half is `googleapps/specreview.py` (`agenda_from_spec_review`, or the model-free `agenda_from_result` from blockers plus the ratsnest; `sendUpdates=all`, a Meet `createRequest`, every unrouted net named, the description HTML-escaped) and the `spec_review` destination in `service/deliver.py`. Full contract in `docs/spec-review.md`.

- **`meetings/`** — the Google Meet front end: a meeting states a hardware requirement and a board comes back. Structured like `service/` — standard library only, no engine logic — and it reads the **Meet REST API v2** transcript of a conference **after it ends**, which is a deliberate rejection of how every open-source meeting bot works: no headless browser joining as a fake participant, no uninvited attendee in the room, no Meet Media API, nothing running while the meeting is live. The trade is stated rather than hidden and belongs in any description of the feature: it sees a meeting only when the organiser enabled transcription, and it is **unverified live** — it has never run against a real Google Workspace account, because `meet.py` puts the one HTTP GET behind a `Transport` Protocol (`UrllibTransport` in production, a recorded transport in tests), the same seam `Model`/`ScriptedModel` gives the agents layer, so the whole package tests offline. `config.py` validates once at construction and names what is missing, because a half-configured integration that starts and dies on the first real event is worse than one that refuses to start: `MEET_ACCESS_TOKEN` (required), `MEET_SPACES` (allowlist; empty means every conference the token can see), `MEET_API_BASE` (pinned to v2 so a silent major-version change cannot reshape the response under a parser with no way to notice), `MEET_MAX_AGE_HOURS` and `MEET_MAX_RUNS_PER_POLL` (both there because a first poll against a busy account would otherwise replay months of meetings, each one a paid pipeline run). - **`billing/`** — usage-credit billing over Stripe, structured like `googleapps/`: stdlib-only (no `stripe` SDK) and no engine logic of its own. The model is Devin's, scaled: prepaid **KCU** (1 KCU = one minute of attributable engine wall-clock, stored as integer milli-KCU) drawn down per run, a small entry payment that becomes credit, auto-reload at a threshold, and **overage rather than cutoff** — a run that passes zero finishes and is billed afterwards, because cutting off mid-run burns the model calls already spent and delivers nothing. Money is integer cents and compute is integer mKCU for the same reason `units.py` makes every dimension an integer nanometre: float money drifts, and a balance that drifts cannot be reconciled. Three invariants carry the package. **The ledger is append-only** and the balance is a fold, never a stored mutable number, so it can always be recomputed and diffed against Stripe. **Every grant is idempotent against the Stripe event id** — Stripe delivers at least once and retries any non-2xx for days, so a replayed `checkout.session.completed` raises `ReplayedEvent` rather than crediting twice; the same guard runs *before* any business validation in `settle_overage`; and the idempotency key is the **Checkout Session**, not the event, because one paid session legitimately emits both `completed` and `async_payment_succeeded` with different event ids and an event-id key granted the pack twice for one payment. **Settlement is two-phase** — `begin_settlement` freezes the quantity a charge is built for and `settle_overage` grants exactly that, never a re-read, because an off-session charge is a round trip during which a finishing run would otherwise have its compute written off unbillable and a landing top-up would make a *successful* charge unrecordable. **Reserve, then commit** is the overlay's own arm-then-commit rule in the ledger: a hold is taken before a run and converted to the metered cost after, so two concurrent runs cannot each pass a balance check and jointly overdraw, and a failed run costs nothing. `webhook.py` verifies the `Stripe-Signature` HMAC against the **raw bytes** before the body is ever parsed (`slackbot/slack.py`'s rule, sharper reason: a forged Slack event wastes a model call, a forged `checkout.session.completed` grants compute nobody paid for) and answers every malformed shape with one undifferentiated error so the response cannot say which half of the check failed. `transport.py` is the `Transport` seam with an exact-match host allowlist enforced at request-construction time — so it holds for the fakes too — and it refuses redirects, since a 3xx would carry the Authorization header off-allowlist. Two Stripe rules are load-bearing and easy to get wrong: `payment_method_types` is **never** sent (omitting it enables dynamic payment methods; hardcoding `['card']` is a conversion bug), and `checkout.session.completed` is **not** proof of payment — with a delayed-notification method it arrives while the session is still `unpaid`, so `fulfillment.py` handles it *and* `checkout.session.async_payment_succeeded` and gates both on `payment_status`. `OveragePolicy.limit_mkcu` is a real credit line and `TopUpPolicy.monthly_cap_cents` a real ceiling: this bills an agent, a retry loop is the normal failure mode, and auto-reload without a cap turns that loop into an unbounded card charge. There is no account system in the repo, so `accounts.py` is an `AccountId` seam (the `Model`/`Transport` convention) with `SingleAccountResolver` as the honest default. `scripts/check_no_keys.sh` is a pre-commit hook that refuses a commit carrying a Stripe key; a live key is fatal, a test key needs `--no-verify`. **`oauth.py` is the browser consent flow** — Stripe really does publish one for your own account, contrary to what this file and the Settings pane both asserted until 2026-09-06: `mcp.stripe.com`'s protected-resource document names `access.stripe.com/mcp`, which advertises Dynamic Client Registration, PKCE **S256** and `token_endpoint_auth_methods_supported: ["none"]`, i.e. a public native client with **no client secret to ship**. It is structurally the flow `googleapps/auth.py` already runs (loopback redirect, code exchange, refresh, 0600 token) and is driven by `POST /billing/connect` (202, because consent waits on a human) polled via `GET /billing/connect`. Two details are load-bearing: RFC 8414 puts the metadata at `access.stripe.com/.well-known/oauth-authorization-server/mcp` — **path insertion, not suffix**, and Stripe 404s the suffix form; and every URL read out of a discovery document is re-checked against the allowlist before use, since those URLs receive the PKCE verifier and return the token. `transport.OAUTH_HOSTS` is kept **separate** from `ALLOWED_HOSTS` and opted into per request, so the guarantee that an API key can never leave `api.stripe.com` survives the feature. What consent grants is the `mcp` scope, **not an API key** — the REST paths still need the restricted key, and both the pane and `describe()` say so rather than implying otherwise. Connect OAuth is the wrong tool (its response now carries only `stripe_user_id`, with the tokens deprecated in favour of a *platform* secret key a desktop app cannot hold); Stripe Apps OAuth needs marketplace publication. **`sqlite_ledger.py` is the durable ledger** and is a *subclass* of `MemoryLedger` overriding a six-method storage seam and nothing else — a durable ledger that reimplements reserve/commit/release will drift from the tested one and then the two disagree about money, so `test_the_invariants_hold_on_disk_too` re-runs the 250-op fuzz against a file. Durability is not a nicety: **Stripe retries a webhook for days**, so a restart between the first delivery and the retry meant the replay guard had forgotten the event and one Checkout Session granted the pack twice. Hence `applied` has a UNIQUE key (a dict check is only correct while one process owns the ledger; the app plus `stripe listen` is already two), `synchronous=FULL` with WAL (`NORMAL` can lose the last transactions on power loss — fine for a cache, not for "did we already grant this payment"), integer columns for money and compute, and no UPDATE or DELETE against `entries` anywhere. An unopenable file degrades to `MemoryLedger` *loudly* on stderr; it still does not make the service safe as two replicas. **`paymethods.py` + `settle.py` close the last gap in overage**: `charge_overage` needs a `cus_`/`pm_` pair that nothing kept, so the path existed in pieces and had never run end to end. The store lives on the ledger's own connection and lock (recording a card and granting credit come from one webhook and must not half-commit), it holds tokens rather than card details, one pair per account replaced not accumulated (charging a stale card is a decline on compute already delivered), and `SavedMethod.updated_at` is excluded from equality so "is this still the card" does not depend on a clock. `handle_event` used to ignore setup-mode sessions wholesale — right for credit, wrong for the payment method, which is the *only* event that carries it — so recording now runs before the mode gate and never raises into the webhook path.

- **`googleapps/`** — the Google Workspace delivery layer over `generate_pcb`, structured like `service/`: stdlib-only (no `google-auth`, no `google-api-python-client`) and no engine logic of its own. `python -m googleapps` has three subcommands: `auth` (OAuth 2.0 installed-app flow with S256 PKCE on `http.server`/`urllib` — browser consent, loopback redirect, token stored at `GOOGLEAPPS_TOKEN_PATH` with mode 0600, transparent refresh that persists; the `code_verifier` never touches disk), `check` (reports configuration and token state, purely local), and `run` (the pipeline, then `--chat` posts a cardsV2 card to a Chat incoming webhook, `--email` sends the summary with the `.kicad_pcb` attached via Gmail `messages/send`, and `--schedule` creates a Calendar event with a Meet `createRequest` **only when the review found blockers**, saying which way it went either way). Every request goes through the `Transport` seam in `transport.py`, which also enforces an exact-match host allowlist — nothing addresses a non-Google host, and the Chat webhook URL (itself the credential) is validated and masked in every message. `run` pre-flights everything it can before a model call is spent — API key, webhook shape, every address (`addresses.py`, the one place user input reaches a MIME header), `--datasheet` syntax, and a *refreshable* token — file present, refresh token inside, OAuth client configured, refreshed now if expired (the one pre-run step that may touch the network) — because the pipeline can outlast an access token and a failure after the board exists has wasted the expensive part. The transport refuses redirects (a 3xx would otherwise carry the bearer token off-allowlist), and the webhook URL is never shown even as a tail, because its tail is the token. Three details were wrong in the first draft and are now pinned by test: the Calendar insert carries `sendUpdates=all` (without it the event is created and no attendee is told), the Gmail guard is 15 MB of *file* because base64 makes a 20 MB attachment a 27 MB message against a 25 MB cap (the test builds the largest allowed message and measures it), and card text is HTML-escaped because `textParagraph` renders a subset of HTML. The honesty rules carry over: the card and the email name every net in `route.unrouted` verbatim and never say "board ready" over a ratsnest. `runner.py` calls `generate_pcb` exactly as the CLI does, with the CLI's flags under the CLI's names (`-d`, `--model`, `--repairs`, `--no-route`, `--no-review`, `--time-limit`); `tests/test_workspace_end_to_end.py` stubs only the model and the transport, and asserts the `.kicad_pcb` bytes recovered from the Gmail `raw` field reparse with every part — the round-trip property, checked on what left the code. The config and end-to-end test files carry a `workspace_` prefix for the same reason `slackbot/tests/test_http.py` is not `test_app.py`: `scripts/check_docs.py` keys per-module counts by file basename, and `slackbot/` already claims `test_config.py` and `test_end_to_end.py`. Built offline against the documented REST surface and never run against live Google APIs.
- **`zoombot/`** — the Zoom front end: the agent is in the meeting while it happens, not reading it afterwards. Structured like `slackbot/` and `service/` (stdlib only, no engine logic, `runner.py` the only module that knows both Zoom and silkscreen, `generate_pcb` imported inside the call so the webhook process starts without the solver). `app.py` serves `POST /zoom/events` and `GET /healthz` on `ZOOM_PORT` (default 8095, because 8080/8081 are taken here); `rtms.py` verifies the webhook **against the raw bytes before the body is parsed** (`verify_webhook` is the only thing that yields a parsed payload, so no path acts on an unverified body), refuses a delivery older than `MAX_WEBHOOK_AGE_S` (300 s), remembers deliveries by `x-zm-trackingid` (a replayed `meeting.rtms_started` is a second *paid* run; a repeat answers 200 `duplicate`, and `endpoint.url_validation` is exempt so re-validating from the dashboard keeps working), answers the `plainToken`/`encryptedToken` handshake, and opens the signalling-then-media WebSocket pair the `zoom/rtms` sample describes. `agent.py` adds only windowing — live speech arrives in fragments, so chunks are gathered by silence gap (15 s), size (4000 chars) and a two-chunk overlap so a requirement split across a boundary stays quotable, with quotes de-duplicated afterwards so the overlap cannot double the bill and windows under 40 chars never sent, since each window is a paid call — and reuses `meetings.intent.extract_requests` verbatim for the extraction and the quote filter rather than re-deriving gates that must not drift. `meetings/runner.py`'s gates hold: quote not in the transcript → dropped, below `DEFAULT_CONFIDENCE_FLOOR` (0.6) → recorded in `considered` and not built, `ZOOM_MAX_RUNS_PER_MEETING` caps paid runs and says so out loud, `ZOOM_MEETINGS` bounds scope (empty means every meeting the credentials see), nothing is ever ordered. **Two boundaries are stated, not hidden.** RTMS is **receive-only** — nothing in that API makes a sound in a meeting — so `speak.py` is a three-way seam (`MeetingSdkSpeaker` drives the headless container, `ChatSpeaker` posts over the REST API, `NullSpeaker` records) and `AUDIBLE_SPEAKERS` (`{"meeting_sdk"}`) is the single whitelist saying which name means audio actually left, read by `ZoomReport.spoke_via` off the speaker object rather than inferred from config, so "the agent replied" can never read as "the agent spoke out loud". And the container in `bot/` is **a specification plus a refusing stub**: not built or run by the suite, the Zoom SDK binary not vendored (it is downloaded under Zoom's licence), and `control_stub.py` answers every `/say` with `{"spoken": false, ...}` because a stub that answered `true` would put `spoke_via: meeting_sdk` on a report for a room that heard silence. Nothing returns a quiet zero — `HandshakeError` (never authorised), `StreamInterruptedError` (half a meeting, with the chunk count), and `EmptyStreamError` (ended cleanly, nothing said) stay three distinguishable facts. The whole package is **unverified live**: no webhook, stream or chat message has ever reached Zoom from here, and the frame constants (`MSG_TYPE`, `MEDIA_TYPE_TRANSCRIPT`, `STATUS_OK`, `TERMINAL_STREAM_STATES`, the comma-joined handshake base string, the `media_server.server_urls` shape, the seconds-or-milliseconds reading of `x-zm-request-timestamp`) are documented assumptions from the sample, gathered in one block so one live run can correct them in one place. `websocket-client` is the `zoom` extra and is imported lazily inside `websocket_connect`, so a missing package says so by name rather than surfacing as a connection failure. `docs/zoom.md` carries the setup, the scopes and every unverified item.
- **`teamsbot/`** — the Microsoft Teams sibling, file for file. `app.py` serves `POST /api/calls` (Graph calling notifications), `POST /api/messages` (Bot Framework activities, where a typed request actually arrives) and `GET /healthz` on `TEAMS_PORT` (default 3978, the Bot Framework convention; `config.py` validates it 1–65535). Authenticity is proved before the body is parsed: `verify_notification` refuses anything but `RS256`/`RS384`/`RS512` (`none` and the HS* family are how a caller talks a verifier into checking a signature it can forge), an issuer outside `ACCEPTED_ISSUERS`, an `aud` that is not this bot's `TEAMS_APP_ID`, a token outside its window (`CLOCK_SKEW_S` 300, `MAX_TOKEN_AGE_S` 3600), and finally a bad signature — and **a missing `cryptography` or key source is a refusal (`crypto_unavailable`, `no_key_source`), never an exemption**, which is why `cryptography` is the `teams` extra rather than a silent optional: an endpoint that waves a token through because it could not check it is worse than one that is switched off. Notification ids are remembered (derived from content when absent, because "no id" must not mean "always new"), the 202 promises acceptance rather than a board, and one run is concurrent. `graph.py` is a read-only client for the documented surface — client-credentials token from `login.microsoftonline.com` (in memory, never on disk, renewed `TOKEN_SKEW_S` early), `users/{id}/onlineMeetings`, `/transcripts`, `/transcripts/{id}/content?$format=text/vtt` — behind an exact-host allowlist applied at request construction (so it holds for the fakes too) and re-applied to every `@odata.nextLink` and `transcriptContentUrl`, because a link in a response is data from the network and does not get to choose which host receives the bearer token. Redirects are refused everywhere, which deliberately includes the transcript `content` route's legitimate blob-storage redirect: that surfaces as `TeamsRefusedError` naming the redirect, never as a silently empty transcript. Four transcript outcomes are four types — `TranscriptionDisabledError` (never enabled: retrying is pointless, the fix is a meeting setting), `NoTranscriptError` (none yet, or empty), `TeamsAuthError` (401/403, usually the missing Teams application access policy rather than a missing permission) and `TeamsCallError` — because an agent handed `""` concludes the meeting was silent. `agent.py` owns no extraction of its own (a `WindowPolicy` over fragments, then `meetings.intent`), `runner.py` keeps the four gates including **skipping a meeting still in progress**, and `speak.py` mirrors Zoom's three-way seam with `CallingBotSpeaker` / `ChatSpeaker` (`POST /chats/{id}/messages`, `contentType: text` so net names and angle brackets cannot be mis-rendered, over `MAX_MESSAGE_CHARS` refused rather than truncated) / `NullSpeaker` (named `"null"`, because the runner's `"none"` already means "nothing was said at all"). The media half is **unbuilt on purpose**: audio needs Microsoft's .NET Graph Communications media libraries, a media certificate and `Calls.AccessMedia.All`, so `bot/` is the control plane only and its `POST /say` answers **501** with the sentence naming what is missing, which reaches a report as `SpeakError("bot_refused", …)`. **Unverified live** against any Microsoft 365 tenant; `ACCEPTED_ISSUERS`, `OPENID_CONFIGURATION_URLS`, `KEY_HOSTS` and the `19:meeting_…@thread.v2` chat-id form are documentation-derived assumptions, and a wrong issuer refuses every call notification loudly rather than accepting one. Teams' WebVTT carries the speaker's **display name** where Meet carries an opaque participant id — a real difference in what the integration sees, not a choice made here. `docs/teams.md` carries the app registration, the permissions, the access policy and every unverified item.
- **`frontend/`** — a Svelte 5 + Vite plain-JS SPA preserving the Drafting Table/Night token system. **Chat** is the default centre tab: `ConversationView` keeps the user request, one optional clarification, friendly activity summaries, assistant output, failure recovery, and compact artifact cards in one transcript; `ActivityCard` expands bounded raw prompts, responses, and tool payloads. `session.js` saves/opens a size-limited, schema-versioned JSON snapshot of the transcript, trace, result, and board artifact. The initial intent form selects Gemini 3.7 Flash or the available Gemini 3.1 Pro Preview for the root, Auto/Fast/Standard/Deep thinking effort, and an Auto/15/6/3 RPM request pace; Gemini 3 cannot turn thinking fully off, so Fast maps honestly to `low`. The pace survives clarification, retry, and session JSON, and visible `quota.wait` activity distinguishes deliberate spacing from a hung call. `GET /models` disables models the current key does not advertise and supplies the broader retry list. The existing Schematic, Board, and Review tabs remain hash-addressed and cross-highlight findings; solver-Y-up becomes SVG-Y-down exactly once in `board.js`. `src/lib/api.js` remains the only `fetch`; chat streaming never replays a malformed or interrupted paid run. Every server event is also mirrored through the existing scrubbed, bounded debug log, and the in-app console remains the only full debugging surface. Session exports contain raw debug prompts/responses by request and should therefore be treated as sensitive design artifacts. Voice in the SPA is built on the browser's own Web Speech API behind injectable seams in `src/lib/voice.js` (no fetch, no network of its own, and not the service's `/transcribe` route — that is the desktop overlay's push-to-talk path in `app/`): `MicButton` dictates into the intent and clarification fields — final transcripts are appended, never replacing typed text, nothing listens until clicked, and Firefox (no SpeechRecognition) gets an inline notice rather than a dead button — while the Review tab reads findings via `speechSynthesis` (per finding, read-all, stop), and `reviewSpeech` keeps the on-screen honesty out loud: a skipped review is read as "not run" and a failed one as "not known", never as zero findings. The `silkscreen-voice` on/off preference persists like the skin and never enters API requests or saved sessions. The local-Whisper/desktop dictation path (hotkey anywhere, whisper.cpp locally, no browser recognition service) is **not built**; `vendor/openwhispr/` is its read-only reference. Orthogonal to theme, the persisted `paper`/`glass` skin changes material without entering API requests or saved sessions. Every high-level material surface declares a `data-material` role: `chrome`, `panel`, `popover`, and `sticky` receive the skin's backdrop filter; `tint` and `canvas` are explicit no-filter roles that prevent nested blur and preserve the board and schematic drawings. `glass.css` supplies both light and dark translucent palettes plus an opaque reduced-transparency fallback, while `--board-*` remains unchanged.

`data-testid` convention: ids sit only on intrinsic elements, never on component tags, since every component destructures `$props()` without spreading rest props onto a host element; a repeated row (a finding, a board part) shares one id across instances, disambiguated by identity attributes such as `data-ref` or `data-sev` rather than an index suffix, which would make the id encode array position instead of role. Nothing strips these in production — the bundle is same-origin and under 5 KB of attributes, and e2e/agent QA should exercise the shipped build, not a stripped one.

## Verifying against real KiCad

`kiutils` reparsing proves an emitted file is *syntactically* valid, which is
not the same as correct. Two installs exist: KiCad 8.0.9 on James's machine at
`~/AppData/Local/Programs/KiCad/8.0/bin/kicad-cli.exe` (winget,
`KiCad.KiCad --version 8.0.9` — pinned to 8 because that is the format
`emit_kicad_sch` and `emit_kicad_pcb` write, not the winget default of 10), and
KiCad 10.0.6 on Pat's Mac at
`/Applications/KiCad/KiCad.app/Contents/MacOS/kicad-cli`, which reads the
`20240108` format without a migration warning (it writes a `.kicad_prl` beside
the project, proof it read the `.kicad_pro`).

```bash
KC=~/AppData/Local/Programs/KiCad/8.0/bin/kicad-cli.exe   # James (Windows)
KC=/Applications/KiCad/KiCad.app/Contents/MacOS/kicad-cli  # Pat (macOS)
"$KC" sch erc --severity-all -o erc.rpt board.kicad_sch
"$KC" pcb drc --severity-error -o drc.rpt board.kicad_pcb
"$KC" pcb drc --schematic-parity --all-track-errors -o parity.rpt board.kicad_pcb
```

Run all three after any change to `schematic.py`, `routing.py`, `board.py` or
`footprints.py`. This is not ceremony: the first DRC ever run on an emitted
board found a via shorting a foreign track and two sub-clearance gaps on a
seven-part design the whole suite passed, and the first parity run (2026-09-05)
found a `net_conflict` on every signal net (local labels name `/NET` on the
root sheet; the pads said `NET`) plus an orphan SOT-223 tab pad numbered 4
with no symbol pin. The Python tests were then written to catch what DRC and
parity caught (`test_schematic.py`'s net-name and pad-number checks, gated
`kicad-cli` runs in `test_routing.py` and `test_schematic.py`), so they are the
CI-runnable proxy and KiCad is the authority they were calibrated against.

Expected clean state, measured on KiCad 10.0.6 with the LDO and 555-blinker
demo prompts: **ERC** 0 errors; warnings are only `lib_symbol_issues` (every
symbol, including power symbols and PWR_FLAG: "does not include the library
'silkscreen'") and `footprint_link_issues` (every footprinted symbol, the same
library name) — LDO 16, blinker 27 — which is correct, the definitions are
embedded in the file on purpose. **DRC** `--severity-error`: 0 violations, 0
unconnected; `--severity-all` adds only `lib_footprint_issues` (one per
footprint; 3 and 8). The two SOT-223 pad-to-pad violations of the former known
issue 11 and the silkscreen-over-copper warnings are gone. **Parity**
(`--schematic-parity`): 0 issues. KiCad 8 has not been re-run since the
global-label and tab-pad changes; the fixes are net names and pad numbers, so
they are format-independent.

For orientation, ERC/DRC are blind: `pcb render --side top` (and the order
step's `pcb export glb`) is the check that the model's pin-1 dot and the
silkscreen pin-1 dot sit on the same pad, and that a diode's band is on the
pad the schematic calls the cathode (pin 2). Every generated multi-pin
pattern was the library's mirror image until 2026-09-05 and no rule caught it;
`test_footprints.py` now pins the winding and the gated `test_models3d.py`
compares pad 1 with KiCad's own footprint.

CI cannot run any of this; there is no KiCad on the runners and installing one
would dominate the job. It stays a local gate.

## Documentation discipline

The README's measured figures (board size, HPWL) come from `scripts/demo.py`, but they are **not** reproducible on demand and the README no longer claims they are: the demo passes `time_limit_s` and the solve ends "time limit reached, feasible but not proven optimal", so a loaded machine returns a worse feasible answer. Measured 2026-09-06 on one Mac: six idle runs gave `18.25 x 18.00 mm` / `53.0 mm`, six concurrent runs gave `19.60 x 18.55 mm` / `62.0 mm` — same code, same seed, `workers=1`. Treat a shifted number as a load difference until you have ruled that out (run idle, or raise `--time-limit` until the status reads `optimal`); update the README only for a real change, and keep the caveat that says which figures are invariant (parts placed, no overlaps, the file reparsing) and which are load-dependent. Test counts in README/DEVPOST are enforced by `scripts/check_docs.py` in CI, and `check_docs.py --fix` rewrites the stale numbers in place. Unbuilt features are tagged `[not yet built]` in DEVPOST.md — keep unbuilt work visibly unbuilt. `check_docs.py` checks every "N tests" claim in README/DEVPOST against pytest's own collection count: a line naming one of its `MODULES` keys (`packing.py`, `agents/`, `service/`, …) is checked against that module's test files, and every other line is checked against the suite total. There is no `MODULES` entry for `frontend/`, so a frontend/Vitest count quoted in either file would fall through to the suite-total comparison and fail CI — never quote one there.
